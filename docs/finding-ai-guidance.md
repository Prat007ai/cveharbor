# CVEHarbor AI finding guidance

CVE details now include a CVEHarbor AI panel. The customer dashboard and workspace provide a short list of prioritized candidates with links to the same guide. Existing asset imports continue to refresh deterministic inventory/advisory matching; matching and dropdown interaction do not call Azure or wait for inference. Coverage is limited to recorded products, versions and indexed evidence. This does not discover all vulnerabilities or replace endpoint scanning.

The user explicitly chooses Generate fix guide. Only the selected CVE, product/version, matching evidence and bounded public advisory excerpts/references are sent to Azure. Hostnames, customer names, asset notes and other assets are omitted. The existing 6,000-byte admission limit, reviewed model, token reservation and immutable metering remain in force. Source text is untrusted data. Guidance uses applicability, recommended fix, temporary mitigation and verification sections, with source-number references and explicit missing evidence. Answers use plain text, never HTML, and execute no commands or patches. No prompts or answers are persisted in the ledger or browser storage. Closing a guide discards the answer; requesting a new guide uses allowance again. An uncertain response is never retried with a new identifier automatically.

Windows Server build-family differences are flagged for review. The mapping uses Microsoft's [Windows Server release information](https://learn.microsoft.com/en-us/windows-server/get-started/windows-server-release-info). A family mismatch does not establish patch status and does not silently remove a candidate from review.

Personal workspaces require no organization. Each activated user has USD 20 per UTC calendar month, shared across that user's personal customer records. Organization allowances remain USD 20 per month shared by members. A request's route determines its payer; a personal request cannot consume an organization balance. Platform owners activate/pause personal accounts under AI usage administration → Personal workspaces. New personal accounts start paused. Existing organization activation and balances are preserved. No paid activation or testing is part of the deployment itself.

The personal ledger uses three additive tables, two indexes and fifteen accounting/recovery triggers in `deployment/proposals/personal-ai/schema.sql`. Existing ledgers and permissions are retained. Personal requests recheck ownership of the selected customer before reservation, dispatch and answer delivery. Rate limiting, reservation bounds, idempotency, holds, immutable prices and owner reconciliation reuse the organization accounting implementation. Dashboard viewers can inspect usage; only existing platform owners can activate or reconcile. Application customer/organization roles are unchanged.

The report page constructs its hidden printable document only when printing begins. Changing customer or environment invalidates that document. Export refreshes and existing print/focus guards remain in place. Organization finding tables show up to 250 candidates; counts retain the full assessment result and explain truncation.
